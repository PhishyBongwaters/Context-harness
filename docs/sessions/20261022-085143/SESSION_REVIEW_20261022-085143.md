## The trace (t0004, restated t0005)

About 30+ functions across arch/x86, fs/read_write.c, fs/ext4 (file.c, inode.c, extents.c, journal.c, page-io.c, mballoc), mm (filemap.c, page_alloc.c, page-writeback.c), fs/mpage.c, block (bio.c, blk-mq.c, blk-core.c, blk-mq-sched.c). Blocking points: folio locks, free-memory reclaim, journal space, folio writeback completion, journal commit, metadata journal space, request-struct allocation, queue readiness, hardware tags, scheduler budget, plug flush. Key conclusion, stated in both versions: the syscall returns after the data is copied to the page cache and marked dirty; block-layer submission is asynchronous via writeback.

**Correctness note:** this review did not re-validate the function/file claims against the tree. Treat the trace as the model's answer, not as a verified result.
